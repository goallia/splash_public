# 0001: Use GitHub for product docs

| | |
|---|---|
| **Date** | 2026-10-15 |
| **Status** | Accepted |
| **Decided by** | @goallia |

## Context

Product specs, decisions and feedback were spread across several tools. It was hard to see what changed, when, and why.

## Options considered

1. **Keep using separate doc tools** — familiar, but no shared history and hard to link to engineering work.
2. **Move product docs to GitHub** — version history, pull-request reviews, and direct links to issues and code; requires learning a little Git.

## Decision

Keep specs, decision records and issue templates in this repository.

## Why

- Every change is tracked with author and date.
- Specs can be reviewed line by line in pull requests.
- Issues, specs and the project board live next to each other.

## Consequences

- Non-technical stakeholders may need a short intro to GitHub.
- Revisit in 3 months: is the team actually using it?
